# Verified admission worker

This source patch adds an explicit testnet admission operation and a constrained native worker to TON commit `3d478cbde854be03a18ab2a59f8fc3c565cf7d14`. It is under qualification; no production integration or deployment has occurred.

`smc.runGetMethodVerified` supports `open_order_preflight` and `close_order_preflight`. It obtains the master block from tonlib's existing LastBlock signature-chain verifier. Caller-supplied `withBlock`, configuration, c7, and gas limits are forbidden. Account and full configuration proofs must refer to that same accepted full block ID. The proof helper requires the expected network, active account, complete previous-block context, supported VM version, bounded BOCs, and authenticated master/shard timestamps within 30 seconds of host time (at most 3 seconds in the future).

Execution uses the official LiteServer getter context construction: authenticated shard time/LT, balance and extra currencies, address, exact code/data, configuration, previous blocks, due payment, precompiled metadata, global version, and applicable authenticated libraries. A fresh random seed is recorded in the complete serialized c7. Both TVM gas_limit and gas_max are fixed at 1,000,000; ACCEPT cannot enlarge the budget. The operation preserves exact exit code and measured gas. Successful results must have an unchanged c4, empty c5, and the exact admission tuple bound to the payload hash and authenticated execution clock. Missing context, code mismatch, VM failure, budget exhaustion, and an economic rejection remain distinct outcomes.

The executable accepts only this operation and an exact engine address/code hash supplied by its trusted launcher. Its configuration file must be a regular, single-link, non-group/world-writable file owned by the process user. It holds trust/cache state in memory and has no transaction-signing or submission input. Readiness follows verified sync and official proof-validated header/account reads at that exact accepted block. It checks authenticated master/shard clocks and qualified engine code before emitting the typed readiness receipt. Startup is bounded by 600 seconds total and 120 seconds without advancing validated progress. Only startup network failures have a maximum of three transport attempts. User requests have one attempt and a 5-second deadline. It accepts at most 128 jobs, bounds input/output sizes, and enforces CPU, stack, descriptor, and core-dump limits.

macOS rejects a finite RLIMIT_AS and denies the unprivileged physical-footprint limit API. The worker therefore measures its own physical footprint every 20 ms and exits above 512 MiB. This is a watchdog with a sampling interval, not a kernel allocation ceiling. Fixed gas and byte/cell bounds limit work between samples. The parent must additionally own deadlines, process cleanup, and bounded output collection.

Build with pinned CMake/Ninja, the git-pinned submodules, and the macOS SDK: `TON_ONLY_TONLIB=ON`, `TONLIBJSON_STATIC=ON`, `USE_QUIC=OFF`, `TON_USE_ROCKSDB=OFF`, `TON_USE_ABSEIL=OFF`, `CMAKE_OSX_ARCHITECTURES=arm64`, and deployment target 13.0. The supported worker runtime is macOS arm64 (deployment target 13.0 or newer); Linux/Docker admission runtime is not provided by this package. The worker target is built and installed only on Apple platforms. Targets are `ton-admission-worker` and `test-verified-admission`. Build logs and exact inputs are retained outside the source tree in the release qualification workspace. The resulting executable links only the system C++ and System libraries; TON and cryptographic dependencies are static.

The retained mode-0 configuration fixture is deliberately rejected as incomplete context. It is not a positive authenticated-execution receipt. Fresh full-context execution, measured warm latency, adversarial VM/worker tests, and independent final source/build review remain qualification requirements.
