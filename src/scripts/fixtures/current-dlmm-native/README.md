# Current DLMM native originals

These portable fixtures preserve original transaction, before-account and after-account BOCs. String pooling only removes repeated JSON strings; it does not reserialize cells. The test adapters provide synthetic block/head and SQL transport. They do not establish public consensus, deployment readiness or the global ledger qualification fence.

- `pool-operations.json.gz` contains 28 current add, refusal, farm, remove, protected-wallet recovery and outside-manifest public-pool cases from the original collector exports named inside the file.
- `pool-recovery-originals.json.gz` retains full setup and failed, marked and delivered histories for the six default/x6 production-Hub withdrawal recovery cases. Ordinary projection separately checks all T3/X physical movements for duplicate cash.
- `spot-originals.json.gz` contains eight direct Spot cases with the production Hub and original owner dispatch: both directions, fee-bearing delivery and refund, under default/x6 configuration. Producer source lock and completion hashes are embedded.
- `order-originals.json.gz` contains twelve production-Hub Order/TWAP cases: both directions and default/x6, three executed slices, one slice followed by cancellation, and funded expiry without execution. Funding, consumed input, physical output and returned custody remain separate.
- `market-originals.json.gz` contains twenty Spot/Order native captures from a separate deployment with explicit on-chain T3 decimals=9. The vendor stablecoin precision comes from its exact installed native family. Original final-head account envelopes and actually executed canonical wallet getters are retained. The isolated producer completion receipt is embedded. Its executed source snapshot did not change; the independent upstream package.json edit recorded in that receipt removed an unused SoraFS autotest entrypoint.
- `spot-transport.json.gz` is retained historical transport evidence. Its synthetic issuance authority and missing original owner dispatch make it unsuitable for positive current financial qualification. The current Spot test uses it only for explicit refusal checks.

Historical precision brackets in the market fixture adapter reuse unchanged original master account envelopes at synthetic before/execution block anchors. The precision decoder requires equal original master last-transaction LT/hash across the bracket, exact master/wallet family pins and explicit on-chain decimals (or the pinned stablecoin contract's fixed six-decimal rule). Off-chain-only T3 metadata, changed root intervals, missing originals and future execution block anchors remain unresolved. Neither current display metadata nor a remote URI supplies historical precision.

The original producers and immutable source closures remain under the owning web repository's `.local/fresh-consumer-20261018/`, including `spot-ledger-native-v3`, `order-ledger-native-v3` and `market-ledger-native-v5`. Native owner checkout/build state was not modified by the isolated market producer. Failed earlier producer attempts and their diagnostics are retained separately.

Run `npm run test:ledger:market`, `npm run test:ledger:liquidity` and `npm run test:ledger:orders`. These aliases exercise the current proof rules; old ABI positives remain archived. The ordinary Order discovery regression keeps the entire original owner history while selecting only exact original factory dispatches as child-creation authority. Getter or selected original-boundary outages cannot erase that uncertainty.

Protected Order-input-wallet retry and never-funded cancellation are not positive financial completion cases in this business corpus. Their missing physical history/credit remains unresolved; no zero-value settlement is invented. Pool protected-wallet retries are qualified independently. The runtime qualification fence remains until all current product and release gates are accepted.

The persisted market proof also retains the configured source's exact masterchain context and original pool execution envelope. Masterchain and shard identities use canonical signed-decimal shard IDs and independent sequence numbers; tagged-shard account membership is checked. Synthetic test source contexts are labeled and never promoted to live consensus proof. Old cached context is refreshed through the configured source. Evidence has pre-parse count/byte limits: 10,000 graph transactions/64 MiB, 256 execution transactions plus anchor/8 MiB, and a separate 8 MiB archive budget for each token.
